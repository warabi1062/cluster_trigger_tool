# アクティブコンテキスト: Cluster Trigger Tool

## 現在の作業の焦点
現在、Cluster Trigger Toolは基本的な機能が実装された状態です。ユーザーはGUIを通じてトリガーを作成、編集し、JSONファイルとしてエクスポートできます。また、既存のJSONファイルをインポートして編集することも可能です。

現在の主な焦点は以下の通りです：
1. **ユーザーインターフェースの改善**: より直感的で使いやすいUIの実現
2. **バグ修正**: 既知の問題の解決
3. **パフォーマンスの最適化**: 大量のトリガーや状態を含むJSONファイルの処理時のパフォーマンス向上

## 最近の変更
- 初期バージョンのアプリケーションが完成し、基本機能が実装されました
- トリガーカードのUIデザインが改善され、左端に選択された色が表示されるようになりました
- トリガーと状態の複製機能が追加されました
- 分析トラッキング機能が実装され、ユーザーのアクションを追跡できるようになりました

## 次のステップ
1. **テンプレート機能**: 一般的なトリガーパターンのテンプレートを提供する機能の実装
2. **バリデーション強化**: フォーム入力のバリデーションを強化し、エラーメッセージを改善
3. **ローカルストレージ統合**: 作業中のトリガー設定をブラウザのローカルストレージに保存する機能の追加
4. **ドキュメンテーション**: ユーザーガイドやヘルプ情報の追加
5. **テスト強化**: 単体テストと統合テストの追加

## アクティブな決定事項
1. **クライアントサイドのみの処理**: すべての処理はブラウザ内で行い、サーバーサイドの処理は行わない
2. **Material UIの採用**: UIコンポーネントライブラリとしてMaterial UIを使用
3. **Formikによるフォーム管理**: 複雑なフォーム状態の管理にFormikを使用
4. **TypeScriptの活用**: 型安全性を確保するためにTypeScriptを使用

## 現在の課題
1. **大量データの処理**: 多数のトリガーや状態を含むJSONファイルの処理時のパフォーマンス問題
2. **モバイル対応**: モバイルデバイスでの使いやすさの向上
3. **エラーハンドリング**: 無効なJSONファイルのインポート時のエラーハンドリングの改善
4. **アクセシビリティ**: スクリーンリーダーなどの支援技術への対応

## 開発環境
- 開発は主にNext.jsの開発サーバーを使用して行われています
- ESLintとPrettierを使用してコード品質とスタイルを維持しています
- pnpmをパッケージマネージャーとして使用しています
